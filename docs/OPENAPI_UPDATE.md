# Updating the SDK from OpenAPI

As of Phase 3, this SDK is **no longer generated by Speakeasy** on each change. The codebase is maintained manually. When the LambdaDB API changes (new endpoints, request/response shapes), update the SDK as follows.

## OpenAPI spec

- **Spec URL**: the public contract is owned by the backend at
  [lambdadb/lambdadb `api/openapi.json`](https://github.com/lambdadb/lambdadb/blob/main/api/openapi.json)
  since backend PR #498. The latest SDK alignment uses `main`
  [`1c3e7d453cca296a7b2af85a375b4c5016504101`](https://github.com/lambdadb/lambdadb/blob/1c3e7d453cca296a7b2af85a375b4c5016504101/api/openapi.json),
  whose spec was last changed by `17903847dff4e22a65dac18514c482d4ba3e220d`
  (PR #483). Earlier pins below refer to
  [lambdadb/docs `reference/api/openapi.json`](https://github.com/lambdadb/docs/blob/main/reference/api/openapi.json).
- There is no checked-in `.speakeasy/` configuration or full local OpenAPI snapshot.
- **Managed analyzer source**: [`schemas/text-analyzers.json`](../schemas/text-analyzers.json) retains the analyzer excerpt shape and default from [docs revision `3bda642f2e7f4f26432f1dfdcb076f656d50f873`](https://github.com/lambdadb/docs/blob/3bda642f2e7f4f26432f1dfdcb076f656d50f873/reference/api/openapi.json), with its enum extended to the 49 names in [backend merge `55d888299fee44466326a9db8016af9811ade13b`](https://github.com/lambdadb/lambdadb/blob/55d888299fee44466326a9db8016af9811ade13b/core/src/main/java/ai/lambdadb/core/IndexingConstants.java) ([PR #437](https://github.com/lambdadb/lambdadb/pull/437)). It is a locally maintained schema, no longer an exact excerpt of that older OpenAPI revision. This pins implementation source, not deployment evidence. Other API contracts retain their existing pins.

## How to update

1. **Option A – Manual code edits**  
   Edit the relevant files under `src/`:
   - **Models**: `src/models/`, `src/models/operations/` (request/response types, Zod schemas).
   - **API calls**: `src/funcs/` (path, query, body, and error handling).
   - **Config**: `src/lib/config.ts` if server URLs or metadata change.

2. **Option B – One-off Speakeasy run (optional)**  
   No generation command or configuration is maintained in this checkout. If you separately configure the Speakeasy CLI to obtain a reference diff:
   - Run Speakeasy generation **locally** into a separate branch or directory.
   - **Do not** re-enable the old `sdk_generation.yaml` CI workflow; treat the output as a reference and apply only the changes you need into `src/` (and keep `src/client.ts` and any hand-written layers unchanged).

3. **Public API**  
   The recommended entry point is `LambdaDBClient` and `client.collection(name)` in `src/client.ts`. Keep that API stable; map any new backend operations onto it as needed.

## Updating vector constraints

Vector configuration follows OpenAPI revision
[`94a7b71613a3bf217a370d5117b3ff6ddfbae851`](https://github.com/lambdadb/docs/blob/94a7b71613a3bf217a370d5117b3ff6ddfbae851/reference/api/openapi.json).
Caller-provided `dimensions` and optional native `embedding.dimensions` are integers
from 64 through 4096; similarity accepts only `cosine` and `euclidean`.
Request and response schemas enforce these bounds. Native model-specific maxima
remain server-validated. Do not infer model defaults or validate document/query
vector length without the Collection schema. Free-form nested object configs
retain server-side validation.

Preserve the existing caller-provided vector default of `cosine` and omitted native
settings. Preserve inbound null-to-undefined handling for optional native settings.
Invalid outbound configurations fail locally with `SDKValidationError`; invalid
Collection responses fail with `ResponseValidationError`. Removing unsupported
similarity enum members also narrows the public TypeScript API. Qdrant Dot distance
must fail explicitly rather than map to a metric the public contract excludes.

## Updating text analyzers

Update the pinned source schema, `Analyzer` in `src/models/indexconfigsunion.ts`,
and `docs/models/analyzer.md` together. `ClosedEnum<typeof Analyzer>` and both
Zod schemas use the same constant, so the expanded list applies to TypeScript,
request serialization, and response validation without a separate enum copy.
Do not widen the enum to arbitrary strings.

The OpenAPI `default: ["standard"]` describes the server default. Keep the SDK
property optional and leave it omitted on the wire; do not insert a Zod default.
The source has no `minItems` or `uniqueItems`: retain empty arrays, duplicates,
and caller order without adding constraints or normalization. The existing
inbound null-to-undefined handling also remains unchanged.

The deployed server now rejects duplicate analyzer names with HTTP 400
(`Duplicate analyzer: ...`), as implemented in backend
`335cb16fcef5d7b8d60f88c84f2ce2cf87f96939`,
`core/src/main/java/ai/lambdadb/application/validation/Validation.java`.
This is an additional server validation rule; the managed enum schema above
remains unchanged. The SDK preserves the supplied list and surfaces the server
error rather than silently deduplicating it.

Run `npm ci`, `npm run lint`, `npm run typecheck`, and `npm test`. The analyzer
regressions compare the managed source with both Zod schemas, exercise the
public client's create/get paths with mock HTTP, and compile package consumers
without casts. These local checks do not establish live server support.

### Live analyzer smoke

Load the intended environment explicitly when testing from a worktree:

```bash
npm run build
node --env-file=/absolute/path/to/original-checkout/.env.local \
  --test test/integration/text-analyzers-live.test.mjs
```

The test requires `LAMBDADB_BASE_URL`, `LAMBDADB_PROJECT_NAME`, and
`LAMBDADB_PROJECT_API_KEY`; missing values fail the test. It creates a temporary
Collection, verifies all 49 analyzer names through create/get/getSafe, writes a
sample for the original 16 analyzers, and checks positive and negative searches
with both query syntax settings. It also checks Chinese/CJK matching differences, the server
`standard` default, empty arrays, order preservation, and HTTP 400 rejection of
duplicate analyzer settings in a Collection update. Cleanup
verifies Collection absence with a 404, including after validation failures.
The metadata checks allow the server's automatically added reserved `id` field.
This credentialed test is separate from ordinary PR CI.

## Updating query limits

The query count and resource-budget contract is pinned to backend
[`234f6f97814bf0d60604fa45ab2907f1fce88b5a`](https://github.com/lambdadb/lambdadb/commit/234f6f97814bf0d60604fa45ab2907f1fce88b5a)
(PR #472, retaining the count limits from PR #469). See its
[public limits](https://github.com/lambdadb/lambdadb/blob/234f6f97814bf0d60604fa45ab2907f1fce88b5a/api/src/main/java/ai/lambdadb/model/publiccontract/PublicContractConstants.java),
[QueryRequest](https://github.com/lambdadb/lambdadb/blob/234f6f97814bf0d60604fa45ab2907f1fce88b5a/api/src/main/java/ai/lambdadb/dto/QueryRequest.java),
[RerankConfig](https://github.com/lambdadb/lambdadb/blob/234f6f97814bf0d60604fa45ab2907f1fce88b5a/api/src/main/java/ai/lambdadb/dto/RerankConfig.java),
and [resource-budget contract](https://github.com/lambdadb/lambdadb/blob/234f6f97814bf0d60604fa45ab2907f1fce88b5a/docs/design/query-result-limits.md).
This source pin does not establish deployment in any environment.

Query `size`, dense `knn.k`, Bayesian `candidateSize`, and
`rerank.candidateSize` support up to 1000. Keep the rerank schema and cross-field
validation aligned, including `size <= candidateSize` and omitted/null defaults.
Preserve free-form query serialization and server-side validation for ordinary
query size, KNN, and Bayesian budgets; do not insert defaults or rewrite `k`.
Facet bucket limits remain 100. Fetch and List now support 1000; see the read contract below.

Query results and hydrated candidate bodies no longer have aggregate 64 MiB
limits. Internal transport safeguards and rerank text budgets remain unchanged.
The server spools large results and retains the public HTTP and `docsUrl` shapes.
Shared temporary storage exhaustion returns HTTP 503, surfaced by the existing
`ServiceUnavailableError` mapping after the configured retries. Storage failures
cannot trigger rerank `returnOriginal` and never return partial results. The
initial shared budget of 256 MiB is an operational setting, not a public maximum
response size. See [query size and byte limits](native-reranking.md#query-size-and-byte-limits).
Use small fixed tests for 101/1000 acceptance, 1001 rejection, candidate/output
ordering, and unchanged facet/default/error behavior. Generate large download
bodies in the test rather than committing fixtures; verify Query and QuerySafe
can read a complete array larger than 64 MiB and propagate storage HTTP 503
without client fallback. These mocked regressions do not establish deployed
server support. Live tests require a separately verified deployment of this
contract before claiming server support.

## Updating Fetch and List

The read contract is pinned to docs `94a7b71613a3bf217a370d5117b3ff6ddfbae851`
and backend [`0a54b6ecb483ce7df9677ba2071a491f9f9879c9`](https://github.com/lambdadb/lambdadb/blob/0a54b6ecb483ce7df9677ba2071a491f9f9879c9/docs/design/query-result-limits.md).
Fetch accepts 1–1000 nonblank IDs; GET/POST List accepts size 1–1000 with server
default 100. Fetch retains its 64 MiB per-node projected JSON budget and unary
transport limits. Budget exhaustion returns HTTP 400 without partial results;
request fewer IDs or fields, or disable vectors. Shared temporary storage
admission failures return HTTP 503. These source pins do not establish deployment.

POST List allows explicit null for size, pageToken, and filter. Preserve these
values in the body and route public list/listSafe calls containing them to POST;
GET parameters remain non-nullable. Pagination preserves the initial null token
and then uses server tokens. Do not insert a size default.

Keep existing server-side validation for Fetch ID counts/nonblank values, List
bounds, nonempty Collection index configs, write arrays/objects, and delete IDs.
The OpenAPI constraints document server requirements; adding local rejection
would change error classification and validation order. Do not trim, deduplicate,
or truncate inputs. Test wire preservation, nullable routing, pagination, and
server HTTP 400 propagation using small deterministic fixtures.

## Updating native embeddings

Backend OpenAPI `1c3e7d453cca296a7b2af85a375b4c5016504101` supersedes the
earlier `queryText`-only description: native fields accept `knn.queryText`,
ordered `knn.queryInputs`, or a direct `knn.queryVector` that skips inference.
Caller-provided vector fields use only `queryVector`. Preserve free-form SDK
queries and server validation; do not introduce a Collection lookup or
client-side field inference.

The native embedding and unindexed-source contract is pinned to backend
`ff13daf3f4ed40487b2b13522a141265c2f459ab` (PR #481); see
[Native embeddings](native-embeddings.md). Keep native input types, union schemas,
root exports, examples, and consumer tests aligned. Preserve the legacy named
type and explicit true flag for older servers. Do not insert `managedEmbedding`
or model defaults on the wire, and retain strict conflicting-field validation.

`embedding.sourceField` and `rerank.fields` select stored string paths without
requiring source index declarations. Preserve existing local rerank path syntax
and bounds checks. Leave embedding source paths, Collection field types, stored
source/candidate validation, and patch merging to the server. Preserve
raw nested documents, siblings, nulls, and omitted source values on the wire;
do not infer source indexes, unwrap text objects, or merge partial updates in
the SDK. Declared source leaves may be text or keyword, with object ancestors.
The rerank contract in [Native reranking](native-reranking.md) uses the same
source pin; the query resource-budget pin above is unchanged.

Maintain mock HTTP and package-consumer regressions for vector-only Collection
create/update, top-level and nested paths, and raw writes/patches. Candidate
validation failures must surface as `BadRequestError`, including with rerank
`returnOriginal`.
The separate `test/integration/native-stored-text-live.test.mjs` smoke requires
a supporting deployed endpoint and verifies actual embedding, reranking, writes,
and cleanup. Local serialization tests do not prove server inference behavior.

## Updating Cohere providers and embedding sources

The Cohere contract follows backend OpenAPI
[`1c3e7d453cca296a7b2af85a375b4c5016504101`](https://github.com/lambdadb/lambdadb/blob/1c3e7d453cca296a7b2af85a375b4c5016504101/api/openapi.json)
and its [embedding](https://github.com/lambdadb/lambdadb/blob/1c3e7d453cca296a7b2af85a375b4c5016504101/docs/design/native-embedding-config.md) and
[reranking](https://github.com/lambdadb/lambdadb/blob/1c3e7d453cca296a7b2af85a375b4c5016504101/docs/design/native-reranking.md) design contracts.
Its delta from docs `94a7b716` is limited to `EmbeddingConfig`, the new
`EmbeddingSource`, `RerankConfig`, `RerankResponse`, and descriptions for
upsert, update, bulk upsert, and query. No paths or other schemas changed.

- `EmbeddingProvider` includes `cohere`. `EmbeddingConfig` accepts nullable
  `sourceField` or 1–16 strict `sources` entries typed `text`/`image`; requests
  require exactly one non-null form. Responses keep the stored form and normalize
  null to undefined without a cross-field check.
- Keep `model` a string and provider-specific model/dimension/source rules
  (OpenAPI `allOf` conditions) on the server, like existing model maxima.
  Path syntax, duplicate paths, URLs, image formats, and limits also remain
  server validations.
- `RerankConfig` is a provider-discriminated union. Cohere accepts
  `rerank-v5.0-pro`/`rerank-v5.0-fast` and only omitted/null criteria; the
  existing shared rerank bounds still apply locally. `criteriaVersion` adds
  `cohere-relevance-v1`; response provider/model remain strings.
- Direct vectors on native fields and native-field bulk imports need no SDK
  wire change; only descriptions changed.

Mock HTTP and serialization tests cover wire preservation and local rejection.
They do not establish Cohere availability: the server enables it only when the
deployment configures the provider secret.

## CI

- **CI**: `.github/workflows/ci.yaml` runs lint, typecheck, build, and tests on Node 24.
- **Publish**: `.github/workflows/publish.yaml` runs on pushes to `main` and on
  published GitHub Releases. A reviewed merge into `main` with the committed
  `X.Y.Z-dev.0` placeholder publishes an npm `dev` build after package checks and
  deployed live smoke tests pass; no Git tag or GitHub Release is created for it.
  A merge that sets an RC or stable version is verified against production, and
  its GitHub Release publishes with `rc`/`latest`.
  Follow [RELEASING.md](../RELEASING.md); no Speakeasy step is involved.
