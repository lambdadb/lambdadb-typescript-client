`rerank?: RerankConfig | null` selects per-query native reranking; omitted/null
preserves existing behavior. See [Native reranking](../../native-reranking.md)
for its required fields, defaults, constraints, default/custom examples and
eligible fallback policy. Reranking requires positive `size`, a scoring query,
and no `sort`. Existing facet and ref restrictions still apply.

Query `size`, dense `knn.k`, and both candidate budgets support up to 1000 on the
[pinned backend contract](../../OPENAPI_UPDATE.md#updating-query-limits).
Query results and hydrated candidate bodies no longer have an aggregate 64 MiB
limit. Large results use `docsUrl`; exhaustion of the server's shared temporary
storage budget returns HTTP 503 without partial results. See
[query size and byte limits](../../native-reranking.md#query-size-and-byte-limits).
Facet bucket limits remain 100. Fetch and GET/POST List support up to 1000
IDs/documents; List defaults to 100. Fetch retains a 64 MiB per-node JSON budget.
See the [read contract](../../OPENAPI_UPDATE.md#updating-fetch-and-list).
